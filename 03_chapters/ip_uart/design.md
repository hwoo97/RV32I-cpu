# UART IP 설계 (`ip_uart`) — 초안

> 6장 MCU의 `apb_uart`(8N1, 1바이트 버퍼, 인터럽트 없음)를 그대로 두고, 기능을 늘린 **독립 IP**를 새로 만든다. RTL → 자가 검사 테스트벤치 → Genus 합성 → Innovus **블록 PnR**(패드 없음) → 게이트 수준 시뮬레이션(SDF) → LEC까지 한 블록으로 진행한다.
> 상태: **초안 (2026-11-24)** — 기능 범위·목표 클럭·순서는 사용자 결정(아래 9절). 레지스터 맵과 세부 결정(10절)은 사용자 확인 대기.

## 1. 목표와 범위

| 항목 | 내용 |
|------|------|
| 버스 | AMBA APB3 슬레이브, 32비트 워드 접근, 대기 없음(`PREADY = 1`), 잘못된 접근은 `PSLVERR` |
| 프레임 | 데이터 5~8비트, 패리티 없음 / 짝수 / 홀수, 정지 비트 1 / 2, LSB 먼저 |
| 버퍼 | TX FIFO 16 × 8비트, RX FIFO 16 × 10비트(데이터 8 + 그 바이트의 패리티·프레임 오류) |
| 수신 | 16배 오버샘플링, 비트 가운데 세 샘플(7·8·9번째) 다수결, 시작 비트 가짜 검출 거르기 |
| 인터럽트 | 원인별 허용(IER)과 상태(ISR), 출력 `irq` 하나: RX 임계값, TX 임계값, 송신 완료, RX 타임아웃, 오류(오버런·패리티·프레임) |
| 시험 기능 | 루프백(TX 출력을 내부에서 RX로) |
| 보율 | 16비트 정수 분주: 보율 = `PCLK / (16 × (DIV + 1))` |
| 목표 클럭 | **200 MHz (5 ns)**, gpdk045 slow 코너 (합성 제약은 규칙대로 × 0.8 = 4 ns) |
| 빼는 것 | RTS/CTS 흐름 제어, break 검출, DMA, 분수 분주 (필요하면 나중에) |

기존 `apb_uart`와 **레지스터가 호환되지 않는다**(새 IP). 6장 MCU는 계속 `apb_uart`를 쓴다. 같은 4 KB 슬롯에 끼울 수 있도록 주소 입력은 12비트로 둔다.

## 2. 블록도

```
            +--------------------------------------------------------------+
  APB3 ---->| uart_regs  (CTRL, BAUD, FIFO_THR, IER, ISR, decode)          |----> irq
            |    |  TXDATA write                     RXDATA read  ^      |
            |    v                                                 |      |
            | uart_fifo (TX, 16x8)                 uart_fifo (RX, 16x10)  |
            |    |                                                 ^      |
            |    v                                                 |      |
            | uart_tx  <---- tick16 ----  uart_baud  ---- tick16 ---> uart_rx
            |    |                                                 ^      |
            +----|-----------------------------------------------|-------+
                 +--> uart_tx (pin)        loopback mux --------+<-- uart_rx (pin)
```

| 모듈 | 하는 일 |
|------|------|
| `uart_top` | 최상위, 포트·루프백 선택, 모듈 연결 |
| `uart_regs` | APB 디코드, 설정 레지스터, 인터럽트 상태·허용, FIFO 쓰기·읽기 신호 |
| `uart_fifo` | 동기 FIFO (깊이·폭 파라미터, 깊이는 2의 거듭제곱), 개수 출력 |
| `uart_baud` | 16배 틱 생성 (`DIV + 1` 클럭마다 한 번) |
| `uart_tx` | TX FIFO에서 꺼내 시작 · 데이터 · 패리티 · 정지 비트를 보냄 (틱 16번 = 1비트) |
| `uart_rx` | 2단 동기화 → 시작 비트 검출 → 비트마다 다수결 → 패리티·정지 비트 검사 → RX FIFO |

## 3. 레지스터 맵 (오프셋, 32비트 워드)

| 오프셋 | 이름 | 접근 | 비트 |
|------|------|:---:|------|
| `0x00` | TXDATA | W | `[7:0]` 보낼 데이터. TX FIFO가 가득이면 버리고 ISR.TXOVR = 1 |
| `0x04` | RXDATA | R | `[7:0]` 데이터, `[8]` 이 바이트의 패리티 오류, `[9]` 프레임 오류, `[31]` EMPTY(읽을 것이 없었음, 이때 FIFO는 그대로). 읽으면 RX FIFO에서 하나 꺼냄 |
| `0x08` | STATUS | R | `[0]` TX_FULL, `[1]` TX_EMPTY, `[2]` RX_FULL, `[3]` RX_EMPTY, `[4]` TX_BUSY(시프트 중), `[12:8]` TX 개수(0~16), `[20:16]` RX 개수(0~16) |
| `0x0C` | CTRL | R/W | `[0]` TX_EN, `[1]` RX_EN, `[3:2]` 데이터 비트(0 = 5 … 3 = 8), `[4]` 패리티 사용, `[5]` 짝수 패리티(0 = 홀수), `[6]` 정지 비트 2, `[7]` 루프백, `[8]` TX FIFO 비우기(W, 1 쓰면 한 번), `[9]` RX FIFO 비우기(W) |
| `0x10` | BAUD | R/W | `[15:0]` DIV. 보율 = `PCLK / (16 × (DIV + 1))` |
| `0x14` | FIFO_THR | R/W | `[4:0]` RX 임계값(1~16, RX 개수 ≥ 값이면 RXTHR), `[12:8]` TX 임계값(0~15, TX 개수 ≤ 값이면 TXTHR) |
| `0x18` | IER | R/W | ISR과 같은 비트 위치: 1이면 그 원인이 `irq`를 올림 |
| `0x1C` | ISR | R / W1C | `[0]` RXTHR, `[1]` TXTHR, `[2]` TXDONE, `[3]` RXTO, `[4]` RXOVR, `[5]` PERR, `[6]` FERR, `[7]` TXOVR |

- 리셋 값: CTRL = `0x0000_000F`(TX·RX 켬, 8비트, 패리티 없음, 정지 1 = 8N1), BAUD = 파라미터 `DIV_RESET`, FIFO_THR = RX 1·TX 0, IER = 0
- ISR 비트 종류
  - **레벨**(상태에서 바로 계산, 쓰기로 못 지움): RXTHR, TXTHR, TXDONE(TX FIFO 비고 시프트도 끝남), RXTO(아래 6절)
  - **고정**(일이 생기면 1, 1을 써서 지움): RXOVR(RX FIFO가 가득일 때 새 바이트가 와서 버림), PERR, FERR(받은 바이트에 오류), TXOVR(가득일 때 TXDATA 쓰기)
- `irq = |(ISR & IER)`
- `PSLVERR`: 없는 오프셋, 쓰기 전용 읽기(TXDATA), 읽기 전용 쓰기(RXDATA, STATUS) → 아무것도 바뀌지 않고 읽기 값 0

## 4. 송신 (`uart_tx`)
- 대기 중 TX_EN = 1이고 TX FIFO가 비어 있지 않으면 하나 꺼내 프레임을 만든다: 시작(0) → 데이터 N비트(LSB 먼저) → 패리티(사용 시) → 정지 1·2비트(1)
- 프레임 설정은 **프레임 시작 때 붙잡아 둔다** (보내는 중에 CTRL을 바꿔도 그 프레임은 그대로)
- 비트 길이 = 틱 16번. TX_EN = 0이 되면 지금 프레임을 끝내고 멈춘다

## 5. 수신 (`uart_rx`)
- 입력을 2단 플립플롭으로 동기화 (루프백이면 동기화 앞에서 TX 출력으로 바꿈)
- 대기 중 1 → 0 변화를 보면 틱을 세기 시작, 시작 비트 가운데(7·8·9번째 샘플) 다수결이 0이 아니면 **잡음으로 보고 대기로 돌아감**
- 이후 각 비트도 7·8·9번째 샘플 다수결. 패리티 비트 검사 → PERR, 정지 비트(첫 번째)가 0이면 FERR
- 오류가 있어도 바이트는 FIFO에 넣고 오류 비트를 함께 저장 (소프트웨어가 바이트별로 판단). RX FIFO가 가득이면 버리고 RXOVR
- 정지 비트 2 설정이어도 수신은 첫 정지 비트만 검사 (보내는 쪽 정지 비트가 길어도 받을 수 있게)

## 6. RX 타임아웃
- RX FIFO에 바이트가 있는데 **문자 4개 시간** 동안 새 바이트도, 새 시작 비트도, RXDATA 읽기도 없으면 RXTO = 1 (임계값보다 적게 남은 마지막 바이트들을 소프트웨어가 놓치지 않게)
- 문자 시간 = 시작 1 + 데이터 N + 패리티(0·1) + 정지(1·2) 비트. 비트 시간은 틱 16번
- 바이트가 들어오거나(정지 비트 가운데), 새 시작 비트가 확인되거나, RX FIFO를 읽으면 카운터를 처음부터 다시 셈. FIFO가 비면 0

## 7. 보율과 오차 (200 MHz)

| 보율 | DIV | 실제 보율 | 오차 |
|------:|------:|------:|------:|
| 9,600 | 1301 | 9,600.6 | +0.01 % |
| 115,200 | 108 | 114,678.9 | −0.45 % |
| 921,600 | 13 | 892,857.1 | −3.12 % |

- 16배 다수결 수신은 양쪽 오차 합이 대략 ±3 % 안이면 받는다고 보고, 시험에서 보율을 ±3 % 틀어 확인한다 (7·8절)
- 오차가 큰 높은 보율이 필요하면 분수 분주를 나중에 검토

## 8. 검증 계획 (`sim/ip_uart/`)

| 테스트벤치 | 대상 | 내용 |
|------|------|------|
| `uart_fifo_tb` | FIFO | 가득·빔 경계, 동시 쓰기·읽기, 비우기, 무작위 대조(기준 큐) |
| `uart_top_tb` | IP 전체 | APB 마스터 태스크 + 직렬 BFM(보내기·받기, 보율·프레임 설정 가능) + 기준 모델(점수판) |

`uart_top_tb` 시험 목록 (초안)
1. 리셋 값, 레지스터 읽기·쓰기, PSLVERR 경우
2. 송신: 프레임 24가지(데이터 5~8 × 패리티 3 × 정지 2) 모두 BFM이 받아 비교
3. 수신: 같은 24가지, BFM이 보내고 RXDATA로 비교
4. FIFO: 16개 채움 → TX_FULL, 17번째 TXOVR / 수신 17개 → RXOVR, 바이트 순서
5. 오류: 패리티 틀린 바이트 → PERR와 RXDATA[8], 정지 비트 0 → FERR와 RXDATA[9]
6. 인터럽트: 원인마다 IER 켜고 끄며 `irq`, ISR W1C
7. RX 타임아웃: 임계값보다 적게 받고 문자 4개 시간 뒤 RXTO
8. 루프백: 외부 핀과 상관없이 TX → RX
9. 잡음·오차: 시작 비트 앞 짧은 0(한 샘플) 무시, 비트 가운데 샘플 하나 뒤집힘 → 다수결로 정상, 보낸 쪽 보율 ±3 %
10. 무작위: 설정·데이터·간격을 섞어 수백 바이트, 점수판 대조
- 버그 모델: 6장처럼 RTL에 버그를 하나씩 넣는 `define`(예: 패리티 반전, 다수결 대신 한 샘플, FIFO 포인터 한 칸 오류)로 시험이 잡는지 확인
- 두 시뮬레이터: PC xsim(먼저), 서버 Xcelium. 게이트 수준은 서버(SDF slow·fast)

## 9. 사용자 결정 (2026-11-24)
- 순서: **UART IP를 7장 멀티사이클보다 먼저** (LEC 뒤에 하기로 한 #93 순서)
- 기능 범위: **추천안 전체** (1절 표)

## 11. 물리 설계 계획 (요약, 세부는 합성 후)
- **실습 방식으로 진행 (2026-11-24 결정)**: 합성 [syn/ip_uart](../../syn/ip_uart/README.md)(실습 run_synthesis + Genus tcl), PnR [pnr/ip_uart](../../pnr/ip_uart/README.md)(실습 all.tcl), RTL 시뮬레이션 `sim/ip_uart/run_function.tcl`(실습 xrun 명령). 아래 항목 중 SDC 입출력 지연(30 %)·false path, 블록 PnR 구성은 그대로
- 합성: 기존 `syn/common` 흐름 재사용, `TARGET_PERIOD = 5`, IO 지연은 주기의 30 %(APB 쪽, 가정), 직렬 핀은 비동기라 `set_false_path` 검토
- PnR: 패드 없는 **블록**, 이용률 기준 floorplan(약 60~70 %), 핀 배치 파일(APB 왼쪽, 직렬·irq 오른쪽), 전원 링 + 스트라이프, CTS, 배선, 채움 셀 → 넷리스트·SDF·DEF·**블록 LEF** 출력
- LEC: RTL ↔ 합성, 합성 ↔ PnR (6장 `ec/ch06_chip` do 파일 형식 재사용)
