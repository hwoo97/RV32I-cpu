# ch06 예외·인터럽트 설계 (초안)

> 5단계 첫 장. 4단계 MCU의 단일 사이클 코어(`rtl/ch14a_mcu/rv32i_core.v`)를 `rtl/ch06_exception/`에 복사해 **CSR·트랩·인터럽트**를 더한다. 버스·주변장치·메모리·펌웨어 환경은 4단계 것을 그대로 쓴다.
> 기준: RISC-V 특권 명세(Machine 모드, Zicsr). 교재 6장(MIPS)은 원리만 참고한다.
> 상태: **결정 A~H 확정 (2026-11-14, 모두 추천안)**

## 1. 목표
| 목표 | 확인 방법 |
|------|-----------|
| CSR 명령어(Zicsr)와 M 모드 트랩(예외·인터럽트·`mret`) | riscv-tests **원래 환경**(`env/p` 기반)으로 rv32ui 다시 + **rv32mi** |
| 4단계에서 신호로만 내보내던 오류를 트랩으로 | `trap`(잘못된 명령어·정렬 오류) → 예외, `bus_err` → 접근 오류 예외 |
| TIMER 인터럽트를 코어에 연결 | 타이머 인터럽트로 LED를 깜빡이고 UART로 출력하는 C 펌웨어 |
| 리셋 해제 동기화기 | 리셋 해제가 클럭과 맞지 않아도 모든 플립플롭이 같은 에지에서 풀림 |
| 합성 비교 | 같은 SDC 시간 모델로 4단계 MCU(8.5 ns, 23,974 µm²)와 비교 |

## 2. 교재(MIPS)와 RISC-V의 차이
교재 6장은 MIPS의 보조 프로세서 0(CP0)으로 예외·인터럽트를 다룬다. 원리는 같고 이름과 세부가 다르다.

| 개념 | MIPS (교재) | RISC-V (이 설계) |
|------|-------------|------------------|
| 제어 레지스터 | CP0 레지스터 (Status, Cause, EPC 등), `mfc0`/`mtc0`로 접근 | **CSR** (12비트 주소 공간), `csrrw/csrrs/csrrc` (+ 즉치값 형태)로 읽고-쓰기를 한 명령어에 |
| 예외가 난 PC | EPC | `mepc` |
| 원인 | Cause 레지스터의 ExcCode | `mcause` (최상위 비트 = 인터럽트 여부, 아래 = 원인 번호) |
| 부가 정보 | BadVAddr | `mtval` (잘못된 주소 또는 명령어) |
| 처리기 주소 | 고정 주소 | `mtvec` (소프트웨어가 설정) |
| 인터럽트 허용 | Status의 IE, 처리 중 표시 EXL | `mstatus.MIE`, 트랩 때 `MPIE`에 저장 후 0, `mret`이 되돌림 |
| 인터럽트 마스크·대기 | Status의 IM, Cause의 IP | `mie` / `mip` (원인별: 외부 MEI, 타이머 MTI, 소프트웨어 MSI) |
| 복귀 | `eret` | `mret` |
| 시스템 호출 | `syscall` | `ecall` (원인 11 = M 모드에서 호출) |
| 디버그 정지 | `break` | `ebreak` (원인 3) |
| 산술 오버플로 예외 | 있음 (`add`가 오버플로하면 예외) | **없음** — RISC-V는 오버플로로 트랩하지 않는다 (필요하면 소프트웨어가 검사) |
| 지연 슬롯 | 분기 지연 슬롯 안의 예외는 EPC = 분기 명령어, BD 비트 | **없음** |
| 미구현 명령어 | Reserved Instruction | 잘못된 명령어(원인 2), `mtval` = 명령어 |

## 3. CSR 목록 (추천안 — 결정 A)
M 모드만 구현한다 (결정 B). 표에 없는 CSR 주소는 **잘못된 명령어 예외**.

| 주소 | 이름 | 구현 |
|------|------|------|
| `0x300` | `mstatus` | `MIE`(3), `MPIE`(7) 읽기·쓰기, `MPP`(12:11) = `11` 고정(M 모드만), 나머지 0 |
| `0x301` | `misa` | 읽기 전용: MXL = 1(32비트), 확장 = `I`만 (쓰기 무시) |
| `0x304` | `mie` | `MEIE`(11), `MTIE`(7), `MSIE`(3) |
| `0x305` | `mtvec` | BASE(31:2), MODE = 0(직접) 고정 (결정 C) |
| `0x340` | `mscratch` | 32비트 읽기·쓰기 (처리기에서 레지스터 하나를 임시 저장) |
| `0x341` | `mepc` | 31:2 읽기·쓰기, 1:0 = 0 (압축 명령어 없음) |
| `0x342` | `mcause` | 읽기·쓰기 (31 = 인터럽트, 4:0 = 원인) |
| `0x343` | `mtval` | 32비트 읽기·쓰기 |
| `0x344` | `mip` | `MEIP`(11)·`MTIP`(7)는 하드웨어 입력(읽기 전용), `MSIP`(3)는 0 (소프트웨어 인터럽트 없음) |
| `0xB00`/`0xB80` | `mcycle`/`mcycleh` | 64비트 클럭 카운터, 읽기·쓰기 |
| `0xB02`/`0xB82` | `minstret`/`minstreth` | 64비트 완료 명령어 카운터, 읽기·쓰기 |
| `0xC00`/`0xC80`, `0xC02`/`0xC82` | `cycle(h)`, `instret(h)` | 위 카운터의 읽기 전용 별명 (Zicntr) |
| `0xF11`~`0xF14` | `mvendorid`, `marchid`, `mimpid`, `mhartid` | 읽기 전용 0 |
| `0x320` | `mcountinhibit` | 0 고정 (카운터 항상 동작) — 넣을지 시험하며 결정 |
- `time`/`timeh`(`0xC01`/`0xC81`)는 표준 `mtime`이 없으므로 넣지 않는다 (결정 D)
- 읽기 전용 CSR에 쓰려고 하면(`csrrw` 등. 단 `csrrs/csrrc`의 rs1 = x0, `csrrsi/csrrci`의 즉치값 0은 쓰기가 아니라 읽기만) 잘못된 명령어 예외

## 4. 트랩 동작
### 4.1 예외 원인과 우선순위 (같은 명령어에서 여러 개가 겹치면 위쪽)
| 순위 | `mcause` | 원인 | 이 설계에서 생기는 경우 | `mtval` |
|:---:|:---:|------|------|------|
| 1 | 1 | 명령어 접근 오류 | 가져오기 주소가 IMEM 밖 (지금의 `fetch_err`) | 그 주소 |
| 2 | 2 | 잘못된 명령어 | 모르는 명령어, 없는 CSR, 읽기 전용 CSR 쓰기 (지금의 `illegal`) | 명령어 비트 |
| 3 | 3 / 11 | `ebreak` / `ecall` | 해당 명령어 | 0 |
| 4 | 0 | 명령어 주소 정렬 오류 | `jal`·`jalr`·분기의 목적지가 4의 배수가 아님 (예외는 **점프 명령어**에서 남, `mepc` = 점프 명령어) | 목적지 주소 |
| 5 | 4 / 6 | load / store 주소 정렬 오류 | `lw`·`lh`·`sw`·`sh` 주소 정렬 안 됨 (결정 E) | 그 주소 |
| 6 | 5 / 7 | load / store 접근 오류 | 없는 주소, IMEM 쓰기, APB에 `sb`/`sh`, `PSLVERR` (지금의 `data_err`) | 그 주소 |
- 명세의 우선순위 표를 이 설계에 있는 원인만으로 줄인 것이다

### 4.2 인터럽트
- 조건: `mstatus.MIE = 1` 그리고 (`mie & mip`) ≠ 0
- 우선순위: 외부(MEI, 원인 11) > 타이머(MTI, 원인 7). `mcause` = `0x8000_000B` / `0x8000_0007`
- `mip.MTIP` = TIMER의 `irq`(`IE & MATCH`). 지우는 방법은 처리기가 TIMER `STATUS`에 1을 써서 `MATCH`를 지우는 것 (결정 D)
- `mip.MEIP` = MCU 입력 핀 `ext_irq` (2단 동기화). UART 인터럽트는 FIFO와 함께 나중에 (결정 F)

### 4.3 트랩이 일어나는 사이클 (단일 사이클)
한 사이클 = 명령어 하나이므로, 트랩은 **그 사이클의 명령어를 끝내지 않고** 다음 PC만 바꾼다.
```
예외:      그 명령어의 레지스터 쓰기·메모리 쓰기·CSR 쓰기를 막고
           mepc <- PC, mcause <- 원인, mtval <- 정보,
           mstatus.MPIE <- MIE, MIE <- 0, PC <- mtvec
인터럽트:  지금 PC의 명령어를 실행하지 않고 같은 처리 (mepc <- PC = 돌아와서 실행할 명령어)
mret:      PC <- mepc, MIE <- MPIE, MPIE <- 1
```
- **정밀 예외가 저절로 보장된다**: 앞 명령어는 모두 끝났고, 이 명령어와 뒤 명령어는 아무것도 바꾸지 않았다. 파이프라인(8장)에서는 이것을 따로 설계해야 한다
- **메모리 쓰기를 막는 것이 핵심**: store가 정렬 오류·접근 오류면 `dmem_wstrb`를 0으로. 접근 오류는 주소 디코더가 판단하므로, 디코더가 오류면 쓰기를 내보내지 않는 지금 구조(`data_err`이면 쓰기 무시)를 그대로 쓴다
- **APB 대기와 인터럽트**: 코어가 APB 응답을 기다리는 중(`mem_wait`)에는 인터럽트를 받지 않는다. 요청이 시작됐으면 끝날 때까지 유지해야 한다는 버스 규칙(4단계)을 지키기 위해서다. 응답이 `PSLVERR`로 끝나면 그 명령어는 접근 오류 예외로 끝난다
- `minstret`은 정상 완료한 명령어만 센다 (트랩 난 명령어, 대기 중인 사이클은 세지 않음)

## 5. MCU 연결
```
          +-------------------------------- rv32i_mcu ---------------------------------+
 rst_n -->| reset sync (2FF) -> rst_n_s                                                   |
 ext_irq->| 2FF sync ------------------------------> core.irq_ext  (mip.MEIP)            |
          |                     core.irq_timer <---- u_timer.irq    (mip.MTIP)            |
          |  core  <-- fetch_err / data_err ---- bus_mux   (access fault exceptions)     |
          +---------------------------------------------------------------------------------+
```
- 출력 `trap`, `bus_err`는 **관찰용으로 남긴다** (트랩이 일어났다는 1사이클 펄스, 원인별). 테스트벤치는 더 이상 이것으로 FAIL 판정하지 않는다 — 트랩은 정상 동작이 됐기 때문. 대신 "처리기가 없는 상태에서 예상하지 못한 트랩"은 riscv-tests 처리기가 FAIL로 보고한다
- 리셋 동기화기는 `rv32i_mcu` 안(합성 대상)에 둔다: 리셋 걸림은 비동기(바로), 풀림은 클럭에 맞춰 2사이클 뒤 (결정 G)

## 6. 시험 계획
| 순서 | 대상 | 방법 | 기준 |
|:---:|------|------|------|
| 1 | CSR 파일 단독 | 테스트벤치(읽기·쓰기·고정 비트·카운터·트랩 갱신) | 자가 검사 PASS, 버그 모델 검출 |
| 2 | 코어 + 메모리 (4단계 `core_wait_tb`와 같은 틀) | riscv-tests **원래 환경 기반** `env/mcu_p`(아래), 무작위 대기 | rv32ui 40 + `ma_data`, rv32mi 목표 목록 PASS |
| 3 | MCU 전체 | `mcu_tb` (TOHOST) | rv32ui·rv32mi |
| 4 | 펌웨어 | ~~C 트랩 처리기·타이머 인터럽트 `fw/timer_irq`~~ → **7단계 보드 데모 때** (2026-11-14 결정) | 하드웨어 확인은 1~3번(어셈블리 트랩 시험 포함)으로 충분. 6장에서는 기존 `fw/hello`를 6장 MCU에서 회귀만 |
| 5 | 회귀 | `fw/hello`, 4단계 시험 | PASS |
| 6 | 합성 | `syn/ch06_exception` (목표 8.5 ns) | 4단계 MCU와 면적·타이밍 비교 |

- **riscv-tests 환경 `sim/riscv-tests-env/mcu_p/`**: 원래 `env/p/riscv_test.h`를 복사해 (BSD) 두 가지만 바꾼다
  - 시작할 때 `.data`를 IMEM → DMEM으로 복사 (4단계 MCU 환경과 같은 이유)
  - `tohost` 기호를 DMEM 끝의 TOHOST 주소에 둔다 (링커 스크립트) → 테스트벤치 감시기를 그대로 쓴다
  - 원래 환경은 PASS/FAIL을 `ecall` → 트랩 처리기 → `tohost` 쓰기로 보고하므로 **트랩 자체가 시험된다**
- **rv32mi 목표**: `mcsr`, `illegal`, `scall`, `sbreak`, `ma_fetch`, `ma_addr`, `csr`, `shamt`, `zicntr`, `instret_overflow`, `l?/s?-misaligned` 4개. `breakpoint`(트리거 모듈 없음 → 테스트가 건너뛰는지 확인), `pmpaddr`(PMP 없음 → 확인)는 시험해 보고 결과에 따라 제외하고 이유를 적는다. `csr`·`scall`은 `misa`로 U·S 모드 유무를 보고 맞춰 동작한다
- **3단계에서 뺀 테스트**: `ma_data`는 정렬 오류를 트랩으로 처리하면(결정 E) 원래 환경에서도 통과 대상이 아니다(하드웨어가 직접 처리하거나 처리기가 흉내 낼 때만 통과) → 결정에 따라 제외 유지 여부를 적는다. `fence_i`는 **명령어를 메모리에 써서 실행**하는 시험인데, 이 MCU는 IMEM에 데이터 쪽 쓰기를 허용하지 않는 구조라(4단계 결정 A) 계속 제외한다

## 8. 범위 밖 (나중 장)
- U·S 모드, `medeleg`/`mideleg`, PMP → 12장(Sv32). riscv-tests `pmpaddr`는 그때까지 제외
- 벡터 방식 `mtvec`, 소프트웨어 인터럽트(`MSIP`), 표준 `mtime`/`mtimecmp` → 필요할 때 (결정 C·D)
- 디버그 모듈·트리거 → 범위 밖 (`tselect`·`tdata1`·`tdata2`는 0 고정으로만 둠)
- UART 인터럽트·FIFO → UART를 인터럽트로 받을 때 (결정 F)

## 9. 결정 (2026-11-14, 모두 추천안(**굵게**)으로 확정)
| # | 내용 | 선택지 | 추천과 이유 |
|:-:|------|--------|------|
| A | CSR 범위 | **3절 표 (M 모드 필수 + 카운터)** / 최소(`mstatus`·`mtvec`·`mepc`·`mcause`만) / 전부(PMP·성능 카운터 등) | 원래 환경 riscv-tests와 rv32mi가 요구하는 것, 펌웨어에 필요한 것(사이클 측정)만. 카운터 64비트 2개가 플립플롭 128개라 면적이 눈에 띄게 늘지만 성능 측정(7·8장 CPI 비교)에 필요 |
| B | 특권 모드 | **M 모드만** / M + U | MCU 펌웨어는 M 모드로 충분. U 모드는 보호가 필요해지는 12장(S 모드·Sv32)에서 함께 |
| C | `mtvec` 방식 | **직접(처리기 하나)** / 벡터(원인별 주소) | 하드웨어가 단순하고 처리기가 `mcause`로 나누면 된다. 인터럽트 지연이 중요해지면 벡터 추가 (MODE 필드는 WARL이라 나중에 넣어도 소프트웨어 호환) |
| D | 타이머 인터럽트 출처 | **4단계 TIMER의 `irq` → `MTIP`** / 표준 `mtime`·`mtimecmp`(CLINT 방식) 새로 추가 | 이미 시험한 TIMER를 그대로 쓴다. 표준 방식은 RTOS를 수정 없이 올릴 때 필요 — 그때 추가(주소 표에 슬롯 하나). 대신 `time` CSR은 없음 |
| E | 정렬 안 된 load/store | **예외(원인 4·6)** / 하드웨어가 두 번 나눠 접근 | 명세상 둘 다 허용. 단일 사이클에서 나눠 접근하려면 메모리를 두 번 읽어야 해 구조가 크게 바뀐다. 결과: `ma_data`는 계속 제외 |
| F | 외부 인터럽트 | **`ext_irq` 핀 하나 → `MEIP` (UART 인터럽트는 나중)** / UART 수신 인터럽트까지 / PLIC 같은 인터럽트 제어기 | 6장의 목표는 트랩 원리. 인터럽트 원인을 늘리는 것은 주변장치 쪽 일이라 FIFO와 함께 |
| G | 리셋 동기화기 위치 | **`rv32i_mcu` 안 (합성 대상)** / 보드 최상위 | 칩에 들어가야 하는 회로라 합성 대상에 둔다. 시뮬레이션에서는 리셋 해제가 2사이클 늦어진다 (사이클 수가 2씩 늘어남) |
| H | `trap`·`bus_err` 출력 | **관찰용 펄스로 남김** / 삭제 | 파형·보드에서 트랩을 바로 볼 수 있어 디버그에 유용, 비용이 거의 없음 |
