# 개요서 — RV32I CPU 설계 및 FPGA 구현 (교재 흐름 기반)

> 최종 갱신: 2026-11-12 (FPGA 보드 데모를 마무리 단계로) · 상태: 초안 (ISA RV32I + 표준 확장, 교재 흐름, Cadence 중심 흐름, Core-5300·gpdk045 확정, 보드 세부 사양은 확인 전)

## 1. 목적
교재 *Computer Principles and Design in Verilog HDL* (Yamin Li, Wiley 2015)의 **CPU 설계 흐름**(단일 사이클 → 예외 → 멀티사이클 → 파이프라인 → FPU → 캐시·TLB → 멀티코어 → I/O)을 따르되 기초 장(1~3장)은 건너뛰고 단일 사이클 CPU 직후 MCU를 먼저 완성하며, 교재의 MIPS 대신 **RISC-V(RV32I와 표준 확장)**로 직접 설계한다. 교재는 원리와 회로 구조를 배우는 데 쓰고, 설계는 RISC-V 명세를 기준으로 처음부터 내 것으로 만든다. 각 설계는 공식 테스트로 검증하고, Zynq-7000 FPGA에서 실행하며, 장마다 FPGA·ASIC(gpdk045) 합성 결과를 남겨 **CPU가 발전하면서 비용과 성능이 어떻게 바뀌는지**를 수치로 보여주는 포트폴리오를 만든다.

**변별력 포인트**: 교재 코드를 옮긴 것이 아니라 같은 흐름을 다른 ISA(업계 표준 RISC-V)로 재설계했다는 점, 공식 테스트(riscv-tests) 통과, FPGA 실행, ASIC 합성까지의 수치.

### 교재(MIPS) → RISC-V로 옮길 때 다른 점
| 항목 | 교재 MIPS | 이 프로젝트 RISC-V | 영향 받는 장 |
|------|-----------|--------------------|------------|
| 명령어 형식 | R/I/J 3가지 | R/I/S/B/U/J 6가지, 즉치값 비트가 흩어져 있음 | 4·5 |
| 레지스터 0 | `$0` = 0 | `x0` = 0 (같음) | 5 |
| 분기 | `beq/bne` + 지연 슬롯 | `beq/bne/blt/bge/bltu/bgeu`, **지연 슬롯 없음** | 5·8 |
| 비교 | `slt` + 분기 | 분기 명령어가 직접 크기 비교 | 4·5 |
| 상위 즉치값 | `lui` | `lui`, `auipc` | 5 |
| 함수 호출 | `jal`(`$31`), `jr` | `jal rd`, `jalr rd, rs1, imm` | 5 |
| 예외·인터럽트 | CP0 레지스터, `eret` | Zicsr CSR(`mstatus`, `mtvec`, `mepc`, `mcause`, `mie/mip`), `mret` | 6·8 |
| 파이프라인 분기 처리 | 지연 분기 | 분기 예측 없음(not-taken) + flush, 이후 예측기 선택 | 8 |
| FPU | MIPS 보조 프로세서 1(`lwc1` 등) | F 확장: `f0~f31`, `flw/fsw`, `fcsr`(반올림 모드·예외 플래그) | 9·10 |
| TLB | 소프트웨어가 TLB 미스 처리 | Sv32: **하드웨어 페이지 테이블 워커**, `satp`, 페이지 폴트 예외, S 모드 | 11·12 |
| 멀티코어 동기화 | 교재 방식 | `mhartid`, A 확장(LR/SC·AMO, 선택) | 13 |
| I/O | 메모리 맵 I/O | 메모리 맵 I/O (같음), C 펌웨어로 구동 가능 | 14 |

## 3. 진행 순서와 장별 내용
교재 1~3장(기초·논리 회로·산술)과 15장(연결망 이론)은 건너뛴다. 단일 사이클 CPU를 만든 직후 **MCU(CPU + 버스 + 주변장치 + C 펌웨어)를 먼저 완성**하고, 그 뒤 교재 6~13장 흐름으로 MCU의 CPU를 고도화한다.

| 순서 | 교재 | 주제 | RISC-V 설계·실습 | 검증 | FPGA | 합성 기록 |
|:---:|------|------|------------------|------|:---:|:---:|
| ① | 4·5장 | 단일 사이클 CPU | RV32I 명령어 형식·ALU → RV32I 37개 단일 사이클 CPU, 레지스터 파일, 즉치값 생성기, 제어 유닛 | rv32ui | | ✓ |
| ② | 14장 일부 | **MCU** | 메모리 맵, **APB3** 주변장치 버스·주소 디코더(코어에 대기 신호 추가), 명령어·데이터 메모리 **각 16 KB**(MCU 모듈 바깥, 같은 칩 — ASIC 합성은 메모리 없는 MCU만), GPIO·Timer·UART, C 펌웨어(crt0·링커 스크립트·`printf`) | 주변장치 테스트, 펌웨어 UART 출력 | ✓ 첫 보드 데모 | ✓ |
| ③ | 6장 | 예외·인터럽트 | Zicsr + M 모드 트랩, Timer·외부 인터럽트 → MCU 인터럽트 | rv32mi, 인터럽트 펌웨어 | ✓ 버튼 인터럽트 | ✓ |
| ④ | 7장 | 멀티사이클 CPU | 상태 머신 제어 (선택: M 확장) | rv32ui·rv32mi (+rv32um), 펌웨어 회귀 | ✓ | ✓ ①과 비교 |
| ⑤ | 8장 | 파이프라인 CPU | 5단, 포워딩, load-use stall, 분기 flush, 정밀 예외 | rv32ui·rv32mi, 펌웨어 회귀 | ✓ | ✓ ①·④와 비교 |
| ⑥ | 9·10장 | FPU, CPU + FPU | IEEE 754 단정밀도 연산기, RV32IF, `fcsr` | 기준 모델 비교, rv32uf | ✓ | ✓ |
| ⑦ | 11·12장 | 캐시·MMU | I/D 캐시, TLB, Sv32 하드웨어 페이지 테이블 워커, S 모드 | rv32si 등 | ✓ | ✓ |
| ⑧ | 13장 | 멀티스레드·멀티코어 | hart별 PC·레지스터, 멀티코어, `mhartid` (선택: A 확장) | 멀티 hart 테스트 (+rv32ua) | ✓ | ✓ |
| ⑨ | 14장 나머지 | 추가 I/O | PS/2, VGA, I2C, 패리티·ECC·CRC (PCI는 선택) | 테스트벤치, 보드 | ✓ | ✓ I2C |

> 장 범위가 크면(⑥·⑦·⑧) 절 단위로 나눠 진행한다. FPGA 표시는 계획이며, 보드에 없는 장치는 Pmod 또는 시뮬레이션으로 대체한다.
> **2026-11-12 결정: 보드 확인은 장마다 하지 않고 7단계에서 대표 설계의 PnR·ASIC 검증이 끝난 뒤 한 번에.** 위 표의 FPGA 열은 마무리 단계에서 시연할 후보이며, 장마다의 완료 기준에서는 FPGA 실행을 뺀다.

## 4. 장 하나를 진행하는 절차
1. **읽기** — 교재의 원리·회로도를 읽고 (②는 14장 UART 등 + RISC-V 메모리 맵 관례), 핵심을 `03_chapters/chNN_<주제>/notes.md`에 내 말로 정리
2. **옮기기** — 교재(MIPS) 설계를 RISC-V에 맞게 바꿀 점을 notes.md에 정리 (2절 표 참고, RISC-V 명세 확인)
3. **설계** — 블록 다이어그램을 먼저 그리고, Claude가 Verilog를 작성 → 사용자가 확인
4. **검증** (Linux, Xcelium) — 모듈 테스트벤치 → riscv-tests(CPU 장) → 이전 장 테스트 회귀
5. **FPGA** (마무리 단계, 이 PC) — 검증된 RTL을 가져와 XDC, Vivado 합성·구현, 보드 실행, LED·ILA 확인 (2026-11-12부터 장마다 하지 않음)
6. **합성 기록** — Genus + gpdk045(면적·WNS·셀 수, **주 지표**) + Vivado(FPGA 장, LUT·FF·BRAM·DSP·Fmax 참고) → `04_results/`
7. **기록** — `test.md`에 결과·문제 해결

## 5. 운영 규칙
- **장 단위 진행, 기간 제한 없음.** 장마다 완료 기준(6절)을 만족하면 다음 장으로 간다.
- 앞 장 설계를 고쳐 다음 장으로 가는 경우(5 → 6 → 8 → 10 → 12)에는 **이전 장 폴더를 그대로 두고** 새 폴더에 복사해 고친다 — 장별 비교를 위해.
- 모든 CPU 설계는 이전 장 테스트까지 회귀로 통과해야 한다.
- 합성 결과는 같은 조건(같은 gpdk045 코너·목표 클럭, 같은 FPGA 디바이스)으로 기록한다.
- ASIC 합성은 **목표 주기의 80 %로 합성**(over-constrain)하고 PnR에서 목표 주기를 맞춘다. 결과 표에는 목표 주기와 합성 주기를 함께 적는다 (2026-11-11 결정).
- 코드는 Git 저장소 하나로 PC와 Linux 서버를 동기화한다. 등가성 검사 때만 RTL·넷리스트·스크립트를 교수님 서버로 옮긴다.
- 설계 코드는 Claude가 작성하고 테스트까지 돌린 뒤 사용자가 확인한다 (핵심 포인트 설명 포함).
- 공개 저장소에는 교재 본문·그림을 올리지 않는다. gpdk045 라이브러리·툴 원본 리포트도 올리지 않고 요약만 공개한다.

| 회로 (⑥ FPU, ⑦ 캐시) | 모든 모듈 자가 검사 테스트벤치 PASS, 합성 기록 |

## 7. 포트폴리오로 보여줄 것
- **CPU 발전 비교표**: 단일 사이클 → 멀티사이클 → 파이프라인 → +FPU → +캐시·MMU → 멀티코어의 FPGA 자원·Fmax, gpdk045 면적·타이밍, CPI·벤치마크 사이클
- **동작하는 MCU**: C 펌웨어로 UART 출력·GPIO 제어를 보드에서 시연
- riscv-tests 통과 표, 자가 검사 테스트벤치와 회귀 테스트
- FPGA 실행 영상(C 펌웨어 UART 출력 등)·ILA 파형
- 대표 CPU의 gpdk045 PnR·등가성 검사 결과
- "MIPS 교재 설계를 RISC-V로 옮기며 바꾼 점" 정리 (설계 판단 근거)

## 8. 예외·문제 대응
| 상황 | 대응 |
|------|------|
| 교재(MIPS)와 RISC-V 명세가 다름 | 명세를 따르고, 차이와 이유를 notes.md에 기록 |
| riscv-tests 실패 | 실패한 테스트 이름 → RARS로 같은 코드 단계 실행 → 파형에서 처음 달라지는 지점 확인, test.md 문제 해결 표에 기록 |
| 막혀서 참고할 실행 기준이 필요 | RARS(명령어 단위 결과) 또는 Spike 실행 기록(명령어별 PC·레지스터)과 비교 |
| 보드에 없는 장치(PS/2 등) | Pmod 또는 시뮬레이션으로 대체하고 기록 |
| FPGA 타이밍 미달 | 클럭을 낮추고 critical path 분석을 기록 |
| 시뮬레이션 무한 루프 | 테스트벤치 타임아웃 → FAIL |

## 9. 주요 리스크
| 리스크 | 대응 |
|--------|------|
| 교재 코드를 그대로 쓸 수 없어 막힐 때 기준이 없음 | RARS·riscv-tests를 기준으로 삼고, 모듈 단위로 작게 검증. 교재 회로도를 RISC-V로 옮긴 블록 다이어그램을 먼저 그림 |
| 12장 Sv32는 교재(소프트웨어 TLB)보다 범위가 큼 (하드웨어 워커 + S 모드) | 절 단위로 나눔: 캐시 → TLB → 워커 → S 모드·페이지 폴트 |
| 작업 환경이 세 곳(Linux 서버·이 PC·교수님 서버)으로 나뉨 | Git으로 코드 동기화, 툴별 스크립트를 저장소에 두고 경로는 환경 변수로 분리. 등가성 검사 파일 목록을 `ec/`에 정리 |
| Linux 서버 접근 범위(원격 접속, 사용 기간) | 2단계에서 확인. Claude는 이 PC에서만 실행 가능하므로 서버 실행 결과(로그)는 사용자가 전달 |
| Core-5300 보드 자료 | 공개 자료가 없어 보드 매뉴얼·회로도·마스터 XDC를 학교·제조사에서 확보 |
| Zynq 보드 USB-UART가 PS 쪽일 가능성 | 14장 UART는 Pmod USB-UART 또는 EMIO |
| gpdk045에 SRAM 매크로 없음 | ASIC 합성에서 메모리는 블랙박스로 빼거나 크기를 줄여 비교 (7장에서 결정) |
